# ハロプロお悩み相談室（仮） 仕様書 v1

最終更新: 2026-09-29

## 1. 概要

女の子の悩みを選択式で診断し、結果として「悩みに呼応する歌詞フレーズ」「寄り添いメッセージ」「その曲のハロプロ公式ライブ映像」を返す診断サイト。

| 項目 | 内容 |
|------|------|
| 対象ユーザー | ハロプロを知らない女の子（ハロプロへの入口にする） |
| 置き場所 | `hello-project.jp/nayami`（既存の推し活タイプ診断と同じドメイン） |
| 実装先 | `helloprojects/frontend`（`/shindan` と同じ Next.js + Cloudflare Pages）。`workers/hybrid-router.js` に `/nayami` のルートを追加 |
| 診断方式 | 選択式・結果メッセージは固定文（AI 生成はしない） |
| 歌詞表示 | 歌詞フレーズをテキストで表示する（B 案）。権利者から指摘があれば、映像の再生位置で見せる方式（A 案）に切り替える |

### ハロプロを知らない人向けであることによる制約

- 専門用語（ヲタ用語、メンバーの愛称など）を画面に出さない
- グループ名は正式名称で書く
- 曲は古い曲・マイナーな曲も可。ライブ映像は **直近 5 年以内（2021 年 10 月以降）の公演** を基本とする

## 2. ユーザーフロー

1. トップ: 導入文 +「相談する」ボタン
2. 質問（すべて選択式、3 問）
   - Q1 何についての悩み？
     恋愛 / 友達・人間関係 / 学校・仕事 / 自分のこと（自信・見た目） / 家族 / 将来
   - Q2 カテゴリごとの深掘り（各 3 択程度。例: 恋愛 → 片思い / 失恋した / 相手に尽くしすぎてしまう）
   - Q3 今ほしいもの: 共感してほしい / 背中を押してほしい / 元気になりたい / 思いきり泣きたい
3. 結果ページ（下記）

## 3. 結果ページのレイアウト

ワイヤーフレーム（ユーザー提供イメージ）に準拠。上から順に:

1. ヘッダー
2. **歌詞フレーズ**: 画面上部に大きく、中央揃え、1〜2 行
3. **ライブ映像**: YouTube 埋め込み。そのフレーズを歌う秒数から再生する。埋め込み不可の動画は YouTube へのリンクで代替
4. **グループ名 / 曲名**（例: `モーニング娘。 / シャボン玉`）
5. **寄り添いメッセージ**: 3 段落構成
   - ① 共感（悩みを受け止める）
   - ② 曲の紹介（この曲が何を教えてくれるか）
   - ③ 締め: 「ハロプロはいつだって女の子の味方だよ。」（全結果共通の固定文）
6. **X でシェア** ボタン
7. **「他の{カテゴリ名}ソングを聞く」**: 同じカテゴリの別の結果からライブ映像を 2 本表示

### メッセージのトーン（見本）

> 好きな人に尽くしたい、その気持ちはわかるよ。
> でも、あなたの人生の主人公はあなた。
>
> この曲は人生も恋もあなた自身が主人公ってことを教えてくれる。そんな曲。
>
> ハロプロはいつだって女の子の味方だよ。

- タメ口で、友達に語りかける距離感
- 1 段落 1〜2 文。説教しない

## 4. 診断ロジック

- Q1 + Q2 で「悩みの細分類」を決め、その細分類に紐づく曲の中から Q3（今ほしいもの）に合う 1 曲を選ぶ
- 各曲に `wants`（どの「今ほしいもの」に合うか）のタグを付ける。合う曲がなければ、その細分類の先頭の曲を選ぶ
- 最初の版は **6 カテゴリ × 2 曲 = 12 件** 以上で公開し、あとで細分類ごとに曲を増やす

## 5. データ構造（案）

```ts
type NayamiResult = {
  id: string;                // "love-devote-too-much"
  category: CategoryId;      // "love"
  subcategory: string;       // "devote-too-much"
  wants: WantId[];           // ["push", "empathy"]
  lyricLine: string[];       // 大きく出すフレーズ（行ごと）
  message: [string, string]; // ①共感 ②曲の紹介（③は共通文）
  song: { title: string; group: string };
  video: {
    youtubeId: string;
    startSec: number;
    liveTitle: string;       // 公演名
    liveDate: string;        // YYYY-MM（直近 5 年チェック用）
  };
  verified: boolean;         // 人間の確認が済んだら true
};
```

`verified: false` の結果は本番では出さない。

## 6. データ作成の手順（AI と人の役割分担）

| 工程 | 担当 |
|------|------|
| 細分類ごとの曲候補・グルーピング・歌詞フレーズ候補を出す | AI |
| 曲とフレーズが悩みに合っているか、歌詞が正しいかの確認 | 人 |
| 公式 YouTube で直近 5 年のライブ映像を探し、動画 ID・秒数・公演名を記入 | 人（AI は検索の手伝いまで） |
| 寄り添いメッセージの下書き | AI |
| メッセージのトーン確認・修正、`verified` を true にする | 人 |

## 7. 安全面

- 結果ページの下部に「本当につらいときは」として公的な相談窓口へのリンクを常に表示する
- 非公式ファンサイトである旨と、楽曲・映像・歌詞の権利表記をフッターに記載する
